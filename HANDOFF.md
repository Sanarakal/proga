# Контекст для помощника на новом ноутбуке

## Задача пользователя

Пользователь переносит уже разработанное приложение MAX Workspace на свой
Windows-ноутбук и хочет продолжить улучшать его через ChatGPT/Codex.
Нужно сохранить доступные сессии, не потерять существующие данные и не начинать
разработку заново. Этот документ заменяет необходимость читать предыдущую переписку.

Пользователь не обязан разбираться в Python и Git. По возможности выполняйте
доступные локальные действия сами и объясняйте результат коротко по-русски.
Если у помощника есть только веб-чат, без терминала и доступа к ноутбуку, прямо
скажите об этом и дайте пользователю конкретные команды. Не выдавайте инструкции
за уже выполненные действия. Сама ссылка на GitHub не даёт доступа к локальным файлам.

## Состояние проекта

Версия 1.10 добавляет «Мои посты → Импорт из MAX»: выбор аккаунта, чата
и сообщения, локальное сохранение текста, разметки, ссылок, фото и MP4-видео.
Сложная разметка сохраняется с блокировкой редактирования текста; неподдерживаемые
вложения отклоняются явно. Лимиты и подробности находятся в `WORKSPACE.md`.
Модули: `workspace_post_import.py`, `workspace_post_import_ui.py`.
Проверки: `test_post_import.py`, `render_post_import.py`; реальные аккаунты
и отправки для проверки не используются.

Последние исправления 1.10: история подгружается кнопкой «Загрузить ещё»
с переходом к новой порции, доступны миниатюры вложений. По просьбе пользователя
INLINE_KEYBOARD автоматически пропускается с уведомлением после сохранения;
все фото/видео и текст сохраняются, ссылки внутри кнопок не переносятся.
Проверен сценарий восьми фото с клавиатурой; сбой скачивания любого фото
останавливает импорт без частичного сохранения. Обновление другого ПК: `README.md`.

Обновление на ноутбуке: версия 1.9 добавляет сохранённые посты с форматированием,
ссылками и фотографиями, мастер рассылки, расписание, повторные проходы и отчёт
по каждой отправке. Подробности и ограничения: начало `WORKSPACE.md`.
Новые модули: `workspace_posts.py`, `workspace_posts_ui.py`,
`workspace_broadcast.py`; проверки: `test_workspace_posts.py`.
Фотографии хранятся в SQLite и входят в прежний формат архива переноса.
Создание рассылки не запускает отправку: требуется кнопка «Запустить».
Восстановление старых сессий пользователь отложил; аккаунты для разработки
не подключались, реальные сообщения в MAX не отправлялись.

- Последняя функциональная версия на момент подготовки документа: 1.8.
- Основная версия: Windows-приложение на Python 3.13 и PySide6, не сайт.
- Доступ к MAX использует неофициальную библиотеку `maxapi-python==2.4.1`.
  Работоспособность методов и доставка кодов зависят от MAX.
- Код, тесты, инструкции и сценарии сборки находятся в этом репозитории.
- На исходном компьютере проверялись модульные тесты, макеты обеих тем,
  сборка и запуск EXE в безопасном режиме `--self-test`.
- Перенос проверялся локальным восстановлением во временный каталог без запросов
  к MAX. Это не проверка действительности сессий на сервере или на другом ПК.
- Папки сборки, окружение Python и личные данные намеренно отсутствуют в Git.
- Старый прототип `app.py` сохранён для справки. Он не является точкой входа 1.8.

Версия документа может отстать от последующих изменений. Проверьте текущий код,
`git log -5 --oneline`, `git status` и `WORKSPACE.md`, не откатывайте новые улучшения
к состоянию 1.8 только ради соответствия этому описанию.

## Что уже реализовано

- До 20 аккаунтов, локальные имена, QR-вход, вход по телефону и сохранённой сессии.
- Цветные статусы, причина состояния, ручная проверка и обнаружение потери связи.
- Сбор заданного количества контактов из выбранных чатов несколькими аккаунтами.
- Закрепление исходного чата за каждым аккаунтом, поиск чатов и выбор всех аккаунтов.
- Общий учёт собранных ID и источников, защита от повторного сбора между аккаунтами.
- Игнор недоступных/заблокированных участников, отчёты по фактическим результатам.
- Добавление контактов в целевые группы с проверкой уже присутствующих участников.
- Ограниченная пересылка выбранного сообщения с явным выбором получателей.
- Общая база уникальных ссылок на чаты, импорт XLSX/CSV/TXT, папка «Все чаты».
- История вступлений, общий реестр между аккаунтами, обработка недействительных ссылок.
- Задания, пауза/возобновление с проверками, удаление заданий без потери общего учёта.
- Светлая и тёмная темы, настройки, журналы и локальные отчёты.

Это описание существующего кода, а не гарантия доступности всех операций для
любого аккаунта MAX. Не обещайте обход ограничений, приватности или блокировок.

## Порядок работы на ноутбуке

1. Уточните, требуется ли только установка/перенос или уже есть новая задача
   по улучшению. Не начинайте произвольный редизайн или рефакторинг.
2. Проверьте Windows, наличие Git и Python 3.13. Выберите обычную папку пользователя
   для проекта. Если репозиторий уже склонирован, проверьте локальные изменения
   перед обновлением; не используйте принудительный сброс.
3. Склонируйте `https://github.com/Sanarakal/proga.git`, если копии ещё нет.
   При отсутствии доступа попросите пользователя авторизоваться в GitHub.
   Вход в браузере сам по себе не гарантирует авторизацию Git.
4. Прочитайте `AGENTS.md`, `TRANSFER.md`, `WORKSPACE.md`. Запустите
   `setup-workspace.ps1`, проверьте успешную установку зависимостей.
5. До первого обычного запуска выясните, перенесены ли `workspace.maxbackup`
   и `workspace.recovery-key`. Попросите только локальные пути, не содержимое.
   Папка переноса может называться `MAX-Workspace-Transfer-<дата>`;
   не подставляйте старое имя пользователя или выдуманный путь.
6. Если файлов нет, продолжайте только безопасную подготовку исходников и тесты.
   Сообщите, что восстановление входов ждёт переноса архива и ключа со старого ПК.
   Не создавайте пустой архив вместо отсутствующего и не обещайте восстановить
   сессии из GitHub: их там нет.
7. Закройте приложение обычным способом. Проверьте, нет ли уже данных в
   `%LOCALAPPDATA%\MAX-Workspace`. Не заменяйте их автоматически. Если это рабочая
   база ноутбука, согласуйте с пользователем, какую копию использовать; слияния нет.
8. Проверьте архив командой `verify`, затем выполните `restore` по `TRANSFER.md`.
   Важно использовать `--recover-orphans`, если файлы сессий сохранились без записей
   аккаунтов. Не изменяйте исходный архив; храните возможность повторного восстановления.
9. Проверьте результат локально: число восстановленных записей, наличие защищённых
   файлов, открытие приложения. Не выводите токены, номера или содержимое ключа.
10. Пользователь выбирает «Аккаунты → Подключить → Сохранённая сессия» для нужного
    аккаунта. Сетевую проверку живых аккаунтов выполняйте только по его запросу.
    Вход по QR/телефону предлагайте, если сохранённая сессия действительно отклонена.
11. Запустите тесты, при необходимости соберите и установите EXE по инструкции.
    Не запускайте реальные задания как способ проверки установки.
12. Сообщите пользователю путь проекта, результат восстановления и проверок.
    После этого переходите к конкретному запрошенному улучшению.

## Особенности сессий и истории

`session.protected` защищён Windows DPAPI исходного пользователя. Просто скопировать
его на ноутбук недостаточно. `transfer_workspace.py` переносит сессии в зашифрованном
архиве и защищает их DPAPI нового компьютера при импорте.

Возможна ситуация: основная база пуста или записи аккаунтов удалены, но файлы
сессий остались. Экспорт сохраняет и такие файлы. При `--recover-orphans` появляются
аккаунты «Восстановленный 1» и далее. После входа пользователь может переименовать их.
Пустая база не доказывает отсутствие файлов сессий, а наличие файла не доказывает,
что MAX разрешит использовать его. Несколько сессий могут относиться к одному
аккаунту; существующая проверка дубликатов MAX ID должна оставаться включённой.

Сессия не содержит всей истории заданий, контактов и исходных чатов приложения.
Если этих данных нет в исходной базе, не обещайте восстановить их из ключа входа.
После импорта нормален статус «Отключён» или «Требуется вход»: соединения между
компьютерами не переносятся, повторно используется сохранённая авторизация.

Архив и ключ нельзя загружать в GitHub, даже приватный, или в чат с помощником.
Для нового переноса после работы на ноутбуке потребуется новый снимок базы.

## Готовность к продолжению разработки

Готовность означает: исходники доступны, зависимости установлены, тесты выполнены,
приложение запускается, перенос либо завершён, либо явно указан его блокер.
Реальный вход и выполнение заданий проверяются отдельно с пользователем.
Не называйте перенос завершённым только потому, что удалось клонировать репозиторий.
